  Two systemic defects in all three shipped bundles

  success = not missing_required and not unexpected     # raw_exit_code recorded
  at 481, never read

  And every task's execution.commands throws the runner's status away before it
  even gets there — kvdex pipes deno test | python3 (status becomes python's),
  android ends ./gradlew … || true, equalsverifier uses
  -Dmaven.test.failure.ignore=true. This is byte-for-byte the defect in your own
  learning/verifier-fail-open.md, which got another EC's ETLCPP bundle bounced
  by a reviewer. CLAUDE.md §10.1 makes it a hard rule and pre-upload checklist
  item 8; the stock harness was never edited. Total build failures still fail
  closed by accident (no PASS lines to parse) — the exposure is a partial run
  where the graded ids print before the process dies.

  2. The test-tree restore can't survive an agent that commits. All three use
  git checkout -- <dir> + git clean -fdq <dir>. git checkout -- with no tree-ish
  restores from the index, and git clean never touches tracked files. An agent
  that runs git add/git commit — codex routinely does — defeats both. This is
  the leading explanation for the equalsverifier bounce, since its zip does
  contain the restore step and the platform still reported both already exists 
  in working directory (new file) and patch failed: InstanceCreatorTest.java:1
  (existing file). Robust shape: rm -rf <testdirs> && git checkout <base_sha> --
  <testdirs>.
