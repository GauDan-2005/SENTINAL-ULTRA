What makes this task difficult?
The obvious implementation of the child CPU fields is wrong, and it is wrong in a way that looks right. A guest calling times() wants the CPU of the children it created and waited for, and the host offers exactly that number for free, so almost every first attempt reads it. It is the wrong number here because the emulator forks its own helper processes for translation and sysroot work, and the host folds their CPU into the same total, so guest programs would see time they never spent. The counters have to be fed only at reaps of processes the guest itself owns. On top of that a single child can be reported more than once, on a stop, on a continue and finally on exit, and a wait can be asked to look at a child without collecting it, so crediting on every report counts the same CPU two or three times. Getting the syscall routed at all is the easy part, since the dispatch header is generated and only builds when the number table, the dispatch manifest and the wrapper all agree.
