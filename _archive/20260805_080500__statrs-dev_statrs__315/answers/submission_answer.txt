The original work adds five hypothesis tests to one module, each a public function with its own error type, registered in the module file, all sharing a new NaN policy enum. The addition is a sixth test in exactly that shape, an Anderson-Darling goodness of fit test, adapted from a later pull request in the same module and the same family of work. Adapted rather than copied: the later version takes no NaN policy and carries a single error variant, while this one follows the conventions the original five established, so it takes a NaN policy and carries two. The original five are untouched and the addition builds on the original's own NaN policy rather than sitting beside it, so the task still maps back to the same piece of work, only bigger. I chose it over the other candidate, statrs pull request 336, https://github.com/statrs-dev/statrs/pull/336, which is a performance rework of the chi-square code, because it alters no observable behaviour and so would have added no difficulty at all. Four wrong but reasonable versions of the statistic were written and scored against the correct one on the same sample. Dropping the index reversal in the second term gives 11.86 where the answer is 0.16, reversing both terms gives 22.76, weighting by 2i instead of 2i-1 gives 2.12, and returning the adjusted figure instead of the unadjusted one gives 0.17. What makes this task difficult?
The work is six separate hypothesis tests and five of them have to land on the same numbers scipy produces, so a formula that looks right is not enough. The Anderson-Darling test is specified on its own terms instead, because scipy's version estimates its parameters from the sample and hands back critical values rather than a p-value. The parts that bite are the ones where the obvious implementation is the wrong one. The Anderson-Darling sum pairs a forward index against a reversed one and the function reports the unadjusted statistic while deriving its p-value from an adjusted one. A single group of repeated values makes the ANOVA call fail even when every other group varies and the groups plainly differ from each other. A group holding one value is perfectly acceptable as long as some other group holds two. The exact Mann-Whitney method carries no size limit of its own, because the size threshold belongs to the automatic mode. A sample whose skew is exactly zero does not give a zero score. Beyond those, Mann-Whitney needs an exact distribution for small samples, a tie correction computed over the two samples pooled rather than each on its own, a continuity correction that applies to one asymptotic variant and not the other, and a choice of which tail each alternative reports. Each test also needs a NaN policy and an error enum whose variants fire on specific inputs in a specific order, so an implementation can compute every statistic correctly and still fail on which error it reports first.

One thing I found and did not fix. The one-sample t-test panics rather than returning a value when every observation is identical, because the variance is zero. That is a real robustness problem and it comes straight from the original work. Grading a panic is not a sensible assertion. I want to be precise about why I left it rather than overstate the case: the instruction does set a blanket numeric agreement requirement that this input falls under, so it is arguable that the allowance for correcting an oracle which does not match its instruction would reach it. I judged that a crash is a different kind of defect from a wrong number, that repairing it means choosing a return value the original work never chose, and that doing so silently inside a difficulty round is the wrong place for it. It is flagged here so the decision is yours rather than hidden. The same applies to a sample where every value is tied, where the score comes back as one through an infinite intermediate rather than as an undefined value. I am reporting it rather than changing it.
